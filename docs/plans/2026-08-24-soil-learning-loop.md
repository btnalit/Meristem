# Soil Learning Loop Implementation Plan

> **For Hermes:** Execute this plan task-by-task with TDD and independent review after each phase.

**Goal:** Complete the soil-owned learning loop so Meristem can distinguish mechanism failures from task failures, accumulate bounded strategy experience, feed validated reflection back to the seed, and gate Stage 5/H1 on real evidence.

**Architecture:** Keep measurement, hidden probes, vault, promotion, credential, worker, and ledger authority in soil. Add a soil-owned attempt/event identity and derived learning projections. Diagnostic review is separate from promotion review and has no merge authority. The seed receives bounded facts, strategy summaries, and explicitly labeled hypotheses only.

**Non-goals:** Do not expose hidden anchor cases or rubric; do not let seed write ledger/scoreboard/report facts; do not start H1 during implementation; do not make Agnes stronger by hard-coding a solution; do not auto-promote diagnostic conclusions.

**Evidence baseline:** `main=faf58a3`; Agnes cycles 21–25 show feedback read but repeated 18-path strategies and `delta=0`; current suite `247 passed, 3 skipped, 71 subtests passed`.

## Phase 0: Design and gate contracts

### Task 0.1 — Add explicit learning-loop design and H1 freeze gate

**Files:** `docs/MERISTEM-V5-SPEC.md`, `docs/MERISTEM-CHECKLIST.md`

Document the state machine, event identity contract, fault taxonomy, task transitions, strategy memory schema, diagnostic review boundary, reflection schema, and Learning Runway. Define Stage 5/H1 as blocked until all soil gates pass.

Acceptance:
- Every event in one attempt can be joined by `attempt_id`.
- `UNFULFILLED` does not equal mechanism failure.
- Diagnostic review cannot produce promotion events.
- H1 gate lists executable evidence commands.

### Task 0.2 — Formalize credential adapter / operator wrapper

**Files:** `docs/MERISTEM-V5-SPEC.md`, `docs/MERISTEM-SOIL-ONTOLOGY.md`, `substrate/run-soil.sh`, `tests/test_credential_adapter.py`, `docs/MERISTEM-CHECKLIST.md`

Replace ad-hoc smoke-shell bridge construction with the contract in S7-Credential Adapter. The wrapper must parse only the checked external assignment-only credential file (never execute/source it), select an allowlisted mode, create an ephemeral soil-owned `0600` pointer target, launch the existing supervisor/gateway path with an allowlisted environment, and clean the file on success, failure, signal, and startup abort. The wrapper must not change gateway/worker ABI or perform provider fallback/promotion decisions.

Acceptance:
- `mode -> source environment variable` mapping is fixed and tested for primary and both explicit backups.
- Inherited provider variables cannot satisfy a missing source credential.
- Source file validation rejects missing, symlinked, non-root-owned, or group/other-readable files.
- Child environment contains the pointer and selected mode, but no provider key or source-only secret.
- Temporary credential file is `soil:soil 0600` while running and absent after normal/non-zero/signal exit.
- Existing gateway, supervisor, security-boundary, and full test suites remain green.

### Task 2.1 — Add RED tests for task transitions

**Files:** `tests/test_task_state.py`

### Task 2.2 — Implement soil-owned task state projection

**Files:** `substrate/task_state.py`, `substrate/feedback_projection.py`, `meristem/task.py`

Acceptance:
- Same task is not retried forever after configured semantic-failure threshold.

## Phase 3: Strategy memory and diagnostic review

### Task 3.1 — Add RED tests for strategy fingerprints

**Files:** `tests/test_strategy_memory.py`

Test stable fingerprints from changed paths and normalized diff metadata, repeated strategy counting, no mutation body storage, and task-scoped aggregation.

### Task 3.2 — Implement bounded strategy memory

**Files:** `substrate/strategy_memory.py`, `substrate/feedback_projection.py`, `substrate/supervisor.py`

Record task-scoped strategy fingerprint, path families, attempt count, best delta, last outcome, repeated flag, and novelty. Store only soil-derived metadata; never persist full prompt/response/diff body in the seed projection.

Acceptance:
- Cycles 21/23/24/25-style repeated path changes produce one strategy cluster with count 3+.
- Different path families remain distinct.
- Projection tells seed what strategy class has failed repeatedly.

### Task 3.3 — Add diagnostic review contract tests

**Files:** `tests/test_diagnostic_review.py`

Verify diagnostic review can inspect bounded diff metadata and task facts, returns schema-constrained diagnosis, cannot write ledger/scoreboard or invoke promotion, and is not called as a prerequisite for accepting progress.

### Task 3.4 — Implement diagnostic review as soil-only adapter

**Files:** `substrate/diagnostic_review.py`, `substrate/supervisor.py`, `soil/model-policies/*.toml`

Run diagnostic review for candidate failures after measurement or contract failure. Prefer deterministic classification first; optional model diagnosis is bounded and non-authoritative. Project only diagnosis class, confidence, evidence cycle IDs, and next-experiment constraints.

Acceptance:
- `PATH_VIOLATION`, repeated strategy, unchanged probe, broad scope, and mechanism fault are distinguishable.
- No diagnostic result can create `accepted_fitness` or `promotion_committed`.
