# memory-graph

This organ builds a decaying knowledge graph over Meristem's own records — patterns, gaps, backlog entries, journal cycles, and organs — so that relations like "P-013 repaired P-008" or "G-006 was diagnosed from eleven wasted cycles" become queryable rather than buried in prose. It reads state/ and answers questions over the organ ABI; it never writes to the registers, because the registers are the source of truth and a derived view must not become a second one. Its utility is measured by usage (how often the kernel or other organs query it) and by node_count and query_latency_ms; it should be pruned when the graph consistently fails to surface useful relations during cycle work — that is, when querying it before a task does not change what the seed does — or when its maintenance cost (extract/edge/decay complexity) exceeds the value of the relations it surfaces.
